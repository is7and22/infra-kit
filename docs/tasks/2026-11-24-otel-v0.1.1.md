主題歸：mini-16（協調 session 名稱，回報與提問用 SendMessage 傳給它）
角色：backend（只動本 repo）

## 一句話

faninsights 接 v0.1.0 時查到兩處要改。一，`otel/nginx/otel.conf` 把 `otel_exporter`、`otel_trace on` 都放在 http 層，一台 nginx 只能 include 一次；多個項目共用一台 nginx（例如本機開發）時，每個 server 都被開追蹤，第二個項目 include 就 `directive is duplicate`。二，OpenObserve 查不存在的 stream 回 400，`check_trace.py` 只認 404。

  - 不存在的 stream：`HTTP 400`，body `{"code":20002,"message":"Search stream not found: nosuchstream",...}`；traces 與 logs 相同

## 這一步要做

1. **nginx 片段拆兩份**
   - `otel/nginx/http.conf`：只放每台 nginx 只能有一份的東西（`otel_exporter`）。README 寫明 nginx 的擁有者在 http 層 include 一次，接著自己寫 `otel_service_name`；exporter 位址怎麼換成自己的 Collector（片段裡寫範例值或拆成擁有者自己寫，由你定，README 寫清楚）
   - `otel/nginx/server.conf`：每個要追蹤的 server 各 include 一次，放 `otel_trace on`、`otel_trace_context propagate`。README 示範在 include 之後加一行 `otel_span_attr project <項目>`，用來在共用 nginx 的 span 上分出是哪個項目（`otel_span_attr` 能不能放 server 層，先實測；不能就停下來回報）
   - 刪 `otel.conf`。README 分兩種情況寫：一個項目一台 nginx（兩份都 include）／多個項目共用一台 nginx（擁有者寫 http 層、服務名用中性的名字例如 `dev-nginx`，各項目只在自己的 server include `server.conf`）
2. **`check_trace.py`**：`_search` 回 400 或 404，且訊息含 `stream not found`（不分大小寫），當成「還沒到」繼續等；其他 400 照舊結束碼 2。補測試，假 OpenObserve 回上面那段 400 body
3. **CI 的 nginx 測試**：`test/` 的設定改成一個 http 層 include `http.conf`，兩個 server 各 include `server.conf`（模擬兩個項目），`nginx -t` 通過；再加一個沒 include `server.conf` 的 server
4. README 的「待 faninsights 驗證」更新：欄位名 `service_name`、`trace_id` 已驗證成立；stream 不存在回 400 已處理；`service.instance.id` 展開成 `service_service_instance_id`

## 驗收

1. `test/run.sh`：兩個 server include `server.conf` 時 `nginx -t` 通過；`http.conf` include 兩次時失敗（`duplicate`）。兩段輸出貼進度
2. 傳播實測：帶 `traceparent` 打有 include `server.conf` 的 server，上游收到同一 trace id、新 span id；打沒 include 的 server，上游收到的 `traceparent` 原封不動（span id 不變）。這條證明沒接的項目不受影響
3. `check_trace.py` 測試：假 OpenObserve 先回 400 `stream not found` 兩次再回資料，結束碼 0；回 400 但訊息不同，結束碼 2。突變：判斷拿掉 400，第一條紅
4. GitHub Actions 全綠，`pre-commit run --all-files` 綠

## 最容易漏的地方

- `otel_trace` 若留在 http 層，所有 server 都會起 span；沒接的項目不會有錯誤訊息，只是 OpenObserve 多出別的項目的 span。驗收 2 的「span id 不變」是唯一會紅的地方
- `otel_service_name` 只能在 http 層：共用 nginx 只有一個服務名，項目別只能靠 `otel_span_attr`。README 不要寫成「每個項目各自設服務名」
- 公開 repo：範例項目名用 `<項目>` 或 `example`，不寫實際項目名的設定值
