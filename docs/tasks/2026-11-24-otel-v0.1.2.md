# OTel 元件 v0.1.2：Python 的 log 改走 instrumentation-logging 的 handler

主題歸：mini-16（協調 session 名稱，回報與提問用 SendMessage 傳給它）
角色：backend（只動本 repo）

## 一句話

`otel/README.md` 要各項目設 `OTEL_PYTHON_LOGGING_AUTO_INSTRUMENTATION_ENABLED=true`，這會讓 log 走 SDK 已標 deprecated 的 `LoggingHandler`，SDK 拿掉它的那一版 log 會靜默消失。改成不設它、加 `OTEL_PYTHON_LOG_CODE_ATTRIBUTES=true`，出 v0.1.2。

## 已經做完

- 第一個接入的項目已實測（`opentelemetry-instrumentation-logging` 0.66b2、SDK 1.45.2，Django＋gunicorn、FastAPI、MCP server 三種服務，經 Collector 與直送兩種跑法）：
  - 不設舊變數時，instrumentation-logging 在啟動時自己裝 handler，log 照樣帶 trace id 進 OpenObserve，筆數不變
  - 它的 handler 預設不帶 `code.file.path`、`code.function.name`、`code.line.number`；設 `OTEL_PYTHON_LOG_CODE_ATTRIBUTES=true` 後每一欄與舊做法相同
  - 機制（0.66b2 原始碼）：舊變數為 `true` 時 `LoggingInstrumentor` 跳過自己的 handler 並印「Skipping installation of LoggingHandler…」警告；`OTEL_PYTHON_LOG_AUTO_INSTRUMENTATION`（預設 `true`）決定裝不裝自己的 handler
- 目前提到舊變數的地方：`otel/README.md`「應用端環境變數」表一列、`otel/python/README.md`「待 faninsights 驗證」一條
